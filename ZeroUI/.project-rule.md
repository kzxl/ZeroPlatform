# Project Specific Directives: ZeroUI
- **Core Principle:** Zero GC allocation on hot rendering paths (`Span<T>`, `ArrayPool<T>`, `readonly ref struct`, `NativeMemory`).
- **Target Compatibility:** Maximum compatibility with .NET Framework 4.6.2 and modern .NET 8/9.
- **Rendering Model:** Decoupled Thread Architecture (UI STA Thread decoupled from Worker Calculation & Render Buffers).
- **Single HWND Constraint:** WinForms controls must maintain 1 top-level HWND per composite view (no nested child control explosion).
- **Language Standards:** Adhere strictly to `[AgentOption]/standards/csharp/high-performance-compute.md` and `winforms.md`.
- **UI & Demo Localization Standard:** All UI controls (default property values, `[DefaultValue]`, button captions, annunciator legends) and sample demo applications (layouts, cards, modals, notifications, tooltips, mock data generators) MUST strictly use Standard Technical English. No bilingual mixing or non-English characters in UI library components or demo suites.
- **Neutrality & Third-Party Trademark Protection:** Strictly FORBID citing, naming, or referencing external proprietary projects, competitors, or commercial library brands (e.g. DevExpress, Syncfusion, Telerik, Infragistics, ComponentOne, etc.) across all documentation (`*.md`), architecture files, roadmap proposals, codebase comments, XML docstrings, commit messages, and UI text. Extract only architectural knowledge, mathematical models, and engineering patterns. Always describe features, components, and benchmarks using neutral, standard enterprise technical terminology to prevent trademark, copyright, or licensing liabilities.
- **Toolbox & Control Icon Standard:** All WinForms controls and components MUST be decorated with `[ToolboxItem(true)]` and `[ToolboxBitmap(typeof(ZeroIcons), "<ControlName>.bmp")]`. Icon bitmaps MUST be standard 16x16 32-bit ARGB bitmaps located in `src/ZeroUI.WinForms/Icons/` and embedded via `<EmbeddedResource Include="Icons\*.bmp" />`. Icons must adhere to category color coding (Grids = Sapphire, Charts = Emerald, Editors = Sky/Slate, Industrial = Amber/Crimson, Warehouse = Indigo, Layout = Obsidian Slate) with crisp 1px pixel grid alignment and transparent background.
- **Git Commit Discipline:** Strictly adhere to `R_GIT` and `[AgentOption]/standards/universal/git-commit-standards.md`. Every commit must be atomic (1 feature/control/bugfix = 1 commit). Never bundle multiple distinct controls or features into mega-commits. Production code and unit tests must be committed together. Documentation updates must remain isolated from functional code commits.
- **UI & Theme Synchronization Standard:** Adhere strictly to `.agents/rules/ui-and-theme-synchronization.md` and `docs/standards/theme-and-ui-standards.md`. Zero hardcoded color literals (hex codes, `Brushes.White/Black`, static ARGB) are permitted in XAML or C#. All UI elements must bind to semantic tokens (`{DynamicResource ZeroUI.*}`, `ZeroWpfTheme.*`, `ZeroTheme.Colors.*`). Every custom control must subscribe to central `ThemeChanged` events and update child elements dynamically. All controls must be verified under both Dark and Light skins with minimum 4.5:1 text contrast before commit. Drawer and transient overlays must use floating non-docked overlays with time-based easing to eliminate layout storms.
- **Control Naming, Prefix Standard & 5-Release Deprecation Policy:**
  - **Core Infrastructure & Engine:** MUST retain the `Zero` prefix (`ZeroTheme`, `ZeroDpi`, `ZeroFontCache`, `ZeroIcons`, `ZeroAnimationClock`, `ZeroLocalizer`) to distinguish foundational engines and prevent collisions with .NET runtime APIs.
  - **UI Controls Suite (Canonical `Z` Prefix):**
    - All drop-in controls replacing WinForms defaults or standard UI components MUST use the canonical **`Z`** prefix (e.g., `ZPanel`, `ZGroupBox`, `ZMenuBar`, `ZButton`, `ZLabel`, `ZCheckBox`, `ZRadioButton`, `ZTextBox`, `ZProgressBar`, `ZTabControl`, `ZSplitContainer`, `ZGrid`, `ZChart`).
    - **IntelliSense Ergonomics:** Typing `Z` in the IDE immediately groups and surfaces the entire ZeroUI component palette.
    - **Zero Collision Guarantee:** Prevents naming ambiguity (`CS0104`) with `System.Windows.Forms.*` without requiring cumbersome long suffixes.
  - **Strict Prohibition of `Zero` Prefix in Controls:**
    - Strictly FORBID creating new controls, enums, or components prefixed with `Zero` (e.g. do NOT name classes `ZeroPanel`, `ZeroGroupBox`, `ZeroButton`, `ZeroPanelBorderStyle`).
  - **Backward Compatibility & 5-Release Deprecation Shims (Warp Policy):**
    - When transitioning existing controls or legacy types to the `Z` prefix standard, ALWAYS provide backward compatibility shims/wrappers (`public class <OldName> : <ZNewName>`).
    - Every backward compatibility wrapper MUST be decorated with:
      `[Obsolete("<OldName> is deprecated and will be removed in 5 release cycles. Please migrate to <ZNewName> instead.")]`
    - Shims and obsolete wrappers must be preserved across exactly 5 minor release cycles to ensure zero compilation breaks in consumer projects, after which obsolete shims will be pruned.
- **Issue Resolution, Author Acknowledgement & NuGet Release Protocol:**
  - **Professional Acknowledgement:** When resolving reported GitHub issues or external contributions, always post a polite, appreciative response thanking the author/reporter for their detailed investigation and report.
  - **Transparent Technical Breakdown:** In both the issue response and git commit history (`(fixes #<id>)`), clearly state the root-cause analysis, the reproduction conditions, and the exact architectural/code fix implemented.
  - **Immediate NuGet Package Bump:** Any functional bugfix or patch MUST trigger an immediate SemVer version bump (`Directory.Build.props`) and publication of a new GitHub Release / NuGet package (e.g. `v1.8.0` -> `v1.8.1` for bugfix patches) to ensure downstream consumers and dependent projects immediately receive the fix without delay.
- **Subsystem Modularization & Cluster Package Architecture:**
  - The desktop control suite is strictly partitioned into 6 granular subsystem clusters under `src/WinForms/` and `src/Wpf/`:
    1. **`Common` (`ZeroUI.WinForms.Common`, `ZeroUI.Wpf.Common`):** Foundations, base classes (`ControlBase`, `ZeroWpfControlBase`), buttons, containers, layout, navigation, overlays, feedback, theming, and icons.
    2. **`Editors` (`ZeroUI.WinForms.Editors`, `ZeroUI.Wpf.Editors`):** Standalone single-value input editors (`TextEdit`, `DateEdit`, `CheckEdit`, `ColorPickEdit`, `SpinEdit`, `TokenEdit`, Media editors). Must NOT depend on `Data` or `Industrial`.
    3. **`Data` (`ZeroUI.WinForms.Data`, `ZeroUI.Wpf.Data`):** High-performance virtualized data components (`GridControl`, `TreeList`, `PropertyGridControl`, `PivotGridControl`) and lookup editors. Depends on `Editors` and `Common`.
    4. **`Charts` (`ZeroUI.WinForms.Charts`, `ZeroUI.Wpf.Charts`):** Telemetry, financial, and scientific charting engines. Depends on `Common` and sovereign math adapters.
    5. **`Industrial` (`ZeroUI.WinForms.Industrial`, `ZeroUI.Wpf.Industrial`):** SCADA gauges (`LinearGauge`, `RadialGauge`, `CircularGauge`), `DigitalIndicator`, plant mimic canvas, pipeline flow, BMS, Energy, Petrochem, Process monitoring.
    6. **`Documents` (`ZeroUI.WinForms.Documents`, `ZeroUI.Wpf.Documents`):** Document viewer, PDF viewer (`PdfViewerControl`), and spreadsheet (`SpreadsheetControl`).
    7. **`Metapackage Umbrellas` (`ZeroUI.WinForms`, `ZeroUI.Wpf`):** High-level metapackages referencing all 6 clusters to preserve 100% backward compatibility for existing monolith consumers.
- **Button & Lookup Decoupling Invariants:**
  - **Buttons Placement:** `SimpleButton`, `SplitButton`, and `ButtonGroup` must be physically located in `Common/Buttons/` while retaining the `ZeroUI.WinForms.Editors` and `ZeroUI.Wpf.Editors` namespaces. This prevents circular dependencies when `Common` containers and dialogs embed buttons.
  - **Lookup Grid Placement:** Lookup editors with embedded Grids (`GridLookupEdit`, `SearchLookUpEdit`, `TreeListLookUpEdit`) must be physically located in `Data/LookupEditors/` while retaining namespaces `ZeroUI.WinForms.Editors` and `ZeroUI.Wpf.Editors`. This ensures `Editors` has 0 dependency on `Data`.
- **Dynamic XAML Style Resolution & Namespace Unification:**
  - `ZeroWpfStyles` in `ZeroUI.Wpf.Common` must resolve editor control styles dynamically via resource keys (`GetStyleByName`) to prevent circular assembly references between `Common` and `Editors`.
  - All WPF subsystem assemblies must register `[assembly: XmlnsDefinition("http://schemas.zeroui.com/wpf", "<Namespace>")]` so XAML developers only need one xmlns definition (`http://schemas.zeroui.com/wpf`).
- **Cross-Platform Control Parity Standard:**
  - Features, telemetry models, and controls must maintain symmetric functional, visual, and naming parity across WinForms and WPF.
  - When introducing a control or feature in one framework (e.g., `DigitalIndicator`, `CircularGauge`, `Badge`, `InfoBar`, `AlertBanner`), an equivalent control or shim must be authored in the counterpart framework.
  - Controls must support dual-aliases where naming historically diverged (e.g. `SideNav` / `SideNavControl`, `InfoBar` / `AlertBanner`).
  - Automated parity tests in `tests/ZeroUI.Desktop.Tests/ControlParityInspectionTests.cs` must be maintained and verified to monitor drift across all 6 subsystem assemblies.
