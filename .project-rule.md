# ZeroPlatform Directives

## 1. Architecture & Dependency Invariants
- **Tier 0A (Absolute Bedrock)**: `ZeroPrimitives.Core` has `0` internal `Zero*` dependencies and `0` external NuGet dependencies on `net8.0`.
- **Tier 0B (Core Substrate)**: `ZeroConcurrency`, `ZeroSecurity`, and `ZeroText` depend only on Tier 0A (`ZeroPrimitives.Core`).
- **Tiers 1–5**: Downstream-only DAG ($L_N \rightarrow L_{<N}$); zero circular dependencies across `ZeroPlatform.slnx`.
- **Pragmatic Dual-Tier Allocation**: Zero heap allocations on hot paths (`Span<T>`, `ref struct`, `ArrayPool<T>`, SIMD intrinsics); idiomatic minimal-allocation OOP on cold paths.

## 2. Versioning & Release Governance (SSOT)

`ZeroPrimitives` is versioned and released **independently** from `ZeroPlatform` inside this monorepo.

| Change Scope | File to Edit | Bump Rule | Git Tag & Workflow | Forbidden Action (Guardrail) | Verification Criterion |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`ZeroPrimitives` patch/bugfix** | `ZeroPrimitives/Directory.Build.props` (`VersionPrefix`) | `3.1.x` -> `3.1.(x+1)`; keep `AssemblyVersion` frozen at `3.1.0.0` (and `MAJOR.0.0.0` from `4.0.0`) | `primitives-v<VersionPrefix>` -> `.github/workflows/publish-packages.yml (`publish-primitives` job)` | Never edit root `Directory.Build.props` for a primitives-only release; never downgrade below `3.1.0` | `dotnet test ZeroPrimitives/tests/ZeroPrimitives.Tests/ZeroPrimitives.Tests.csproj -c Release` passes on both `net8.0` and `net462` (exit `0`); `.nuspec` has `0` `Zero*` deps |
| **`ZeroPrimitives` minor feature** | `ZeroPrimitives/Directory.Build.props` (`VersionPrefix`) | `3.x.y` -> `3.(x+1).0`; keep `AssemblyVersion` frozen at `3.1.0.0` | `primitives-v<VersionPrefix>` -> `.github/workflows/publish-packages.yml (`publish-primitives` job)` | Never break public signatures in minor releases; annotate relocations `[Obsolete]` for >= 1 minor cycle | `dotnet test` (`net8.0` + `net462`) exit `0`; `AssemblyVersion` unchanged in packed DLLs |
| **`ZeroPrimitives` breaking major** | `ZeroPrimitives/Directory.Build.props` (`VersionPrefix` & `AssemblyVersion`) | `MAJOR` + 1 (`4.0.0`); set `AssemblyVersion` = `MAJOR.0.0.0` (`4.0.0.0`) | `primitives-v<VersionPrefix>` -> `.github/workflows/publish-packages.yml (`publish-primitives` job)` | Never couple `ZeroPrimitives` major bumps to `ZeroPlatform` UI/tier-5 breaks | Full `ZeroPlatform.slnx` build + `ZeroPrimitives.Tests` (`net8.0` + `net462`) exit `0` |
| **`ZeroPlatform` release (Tiers 0B–5)** | Root `Directory.Build.props` (`PlatformVersion`) | SemVer on `PlatformVersion`; keep `AssemblyVersion` frozen at `3.1.0.0` during `3.x` (`MAJOR.0.0.0` from `4.0.0`) | `v<PlatformVersion>` -> `.github/workflows/publish-packages.yml` | Never pass `-p:Version=...` globally on CLI (clobbers `ZeroPrimitives`); never push `ZeroPrimitives.Core.*.nupkg` from `v*` | `ZeroPrimitives.Core` version in `ZeroPrimitives/Directory.Build.props` is already live on NuGet.org; `dotnet build ZeroPlatform.slnx -c Release` exit `0` |
| **Cross-cutting change (`ZeroPrimitives` + `ZeroPlatform`)** | Both props files | Bump `ZeroPrimitives` first, release `primitives-v*`, wait for NuGet.org indexing, then bump `PlatformVersion` and tag `v*` | 1) `primitives-v*` then 2) `v*` | Never tag `v*` before the required `ZeroPrimitives.Core` version is published on NuGet.org | `publish-packages.yml` NuGet check succeeds; downstream `.nuspec` resolves exact `ZeroPrimitives.Core` version |

### MSBuild CLI Override Rules
- Override `ZeroPlatform` version via `-p:PlatformVersion=X.Y.Z` (safe; leaves `ZeroPrimitives` untouched).
- Override `ZeroPrimitives` version via `-p:PrimitivesVersion=X.Y.Z` (safe; leaves `ZeroPlatform` untouched).
- Prerelease suffixes use `-p:VersionSuffix=<suffix>` (e.g. `primitives-v3.2.0-preview.1`); `FileVersion` remains numeric `$(VersionPrefix).0`.

## 3. Multi-Targeting & Verification Discipline
- Run `ZeroPrimitives.Tests` without `-f net8.0` so both `net8.0` and `net462` execute on every change.
- Do not force higher-tier modules to target `net462`/`netstandard2.0` unless consumer/API requirements demand it (`ZeroPrimitives.Core` and Tier 0B retain `netstandard2.0;net462;net8.0`).
- Stage only in-scope files (`git add <files>`); never commit tracked `.nupkg` artifacts.
